foxreach

Lets any local agent that speaks MCP operate the tabs of a Firefox-based browser, with real input. It has no telemetry, no account, no vendor lock-in and no open network port.

It has two parts: the foxreach program, one file that is the MCP server agents run and the native host the browser starts, and the foxreach add-on in the browser. On Linux, the manager app sets both up from a window.

The program

For Linux and macOS, x86-64 or arm64. Download install.sh from the latest release, read it, and run it:

curl -fLO https://github.com/nilltadios/foxreach/releases/latest/download/install.sh
sh install.sh

install.sh downloads the foxreach build for this machine from the latest release into ~/.local/bin, checks it against the release's SHA256SUMS, and runs foxreach install, which writes the native messaging manifest that lets the browser start it. Installed Flatpak browsers are prepared too.

Later versions: foxreach update. To remove it: foxreach uninstall, then delete ~/.local/bin/foxreach.

Or download the file yourself from the latest release (foxreach-linux-x64, foxreach-linux-arm64, foxreach-darwin-arm64, foxreach-darwin-x64), make it executable, and run ./foxreach install. macOS needs one more step for a file downloaded with a web browser: see Install in the README.

Windows: install.ps1 from the same release does the same (powershell -ExecutionPolicy Bypass -File install.ps1). What has been tested there and what differs: Windows in the README.

The add-on

There are two builds. Which one depends on the browser:

BrowserBuild
Firefox release and beta, distro firefox packages, the Firefox Flatpak The signed build, from addons.mozilla.org. Clicks and keys are script events, which a few sites ignore, and a few tools are missing (drag, read_console, handle_dialog, file drops).
LibreWolf, Firefox Developer Edition, Nightly The full build, with real input and all tools. Mozilla does not sign it, so it is installed with a setup script: Setup from a checkout.
Firefox ESR, Floorp, Waterfox, Zen Either. The full build is expected to work, but has not been tested.

Then click the foxreach toolbar button and choose the sites agents may use. Both builds update themselves: the signed one from addons.mozilla.org, the full one from updates.json on this site.

Connecting an agent

foxreach install also adds the MCP server, foxreach mcp, to every agent it finds on the machine: Claude Code and Claude desktop, Codex, opencode, Cursor, GitHub Copilot CLI, Qwen Code and the others listed in the README. It adds only the foxreach entry to each agent's settings file and backs the file up first.

foxreach agents                       # what it found
foxreach install --agents codex,pi    # name the agents instead
foxreach install --agents none        # skip this step

For any other agent, give it this command as an MCP server:

~/.local/bin/foxreach mcp

The first time an agent calls, the browser asks whether to allow it. foxreach uninstall removes the agents' entries again (--keep-agents keeps them).

The manager app (Linux)

A desktop app that does all of the above from a window: it installs and updates the foxreach program (downloaded from the latest release and checked against SHA256SUMS, as install.sh does), lists every Firefox-based browser profile and opens the signed add-on there for the browser to confirm, adds or removes each agent's entry, and removes any part again. Every change is made by running foxreach itself. More in the manager README.

AppImage

The latest release has foxreach-manager-<version>-x86_64.AppImage and foxreach-manager-<version>-aarch64.AppImage, which run on any distribution:

chmod +x foxreach-manager-*.AppImage
./foxreach-manager-*.AppImage

Without FUSE, add --appimage-extract-and-run. AppImage updaters (Gear Lever, appimageupdatetool, AppImageUpdate) find newer releases from the update information inside the file.

The same release also has foxreach-manager-<version>-<arch>.flatpak for installing without a network (flatpak install --user FILE). A copy installed that way does not update.
